AMAZON E-COMMERCE DB - VIDEO SCRIPT (5-10 min)

[0:00-0:30] INTRODUCTION
"Hi, I'm [Your Name] and this is our Amazon-Style E-Commerce Database project.
We built a MySQL database that models a complete online marketplace, tracking
customers, products, sellers, orders, reviews, and shipping."

[0:30-2:00] DATABASE STRUCTURE
- Open MySQL Workbench EER Diagram (or show a PNG)
- "Our system has 10 tables. Let me walk through the main ones..."
- Customers → can have many addresses and payment methods
- Sellers → list products in categories
- Categories → self-referencing for subcategories (Electronics > Computers)
- Orders → linked to customers and addresses, contain order_items
- Shipping → one record per order with tracking info
- Reviews → customers review products
- Highlight the relationships: 1:N and the M:N between orders/products via order_items

[2:00-3:30] INSERT OPERATIONS
- "First, let's add a new customer..." Run the INSERT INTO customers
- "Now a seller adds a new product..." Run INSERT INTO products
- "Let's add items to an existing order..." Run INSERT INTO order_items + UPDATE order total
- Show the results: SELECT * FROM customers WHERE customer_id = 6; SELECT * FROM products WHERE product_id = 11;

[3:30-4:30] UPDATE & DELETE OPERATIONS
- "We need to update a phone number..." Run UPDATE customers
- "A product sold, so we update stock..." Run UPDATE products stock_quantity
- "An order just shipped..." Run UPDATE orders status + UPDATE shipping
- "A customer wants to cancel their pending order..." Run DELETE FROM orders WHERE order_id = X
- Explain CASCADE: "Notice order_items and shipping were automatically deleted."

[4:30-6:30] QUERIES AND REPORTS
- "Let's search for laptops..." Run search query with LIKE '%Laptop%'
- "Filter products $100-$500..." Run price range query
- "Top-selling products..." Run report query
- "Revenue by seller..." Run revenue report
- "Monthly sales trends..." Run monthly aggregation
- Narrate what each result means for the business

[6:30-7:30] VIEWS
- "We created two views to simplify common queries."
- "First, vw_product_catalog..." Run SELECT * FROM vw_product_catalog LIMIT 5;
- "Second, vw_order_details..." Run SELECT * FROM vw_order_details WHERE order_id = 1;
- Explain why they are useful for the frontend or admin dashboard

[7:30-8:30] FRONTEND DEMO
- "For extra credit, we built a Flask web application that connects to our database."
- Open browser to http://127.0.0.1:5000
- "The home page links to all features."
- Navigate to Products: "Here's our product catalog, pulled from the vw_product_catalog view."
- Click Add Product: "We can add a new product through this form." Fill in fields and submit.
- Click Edit on the new product: "We can also edit existing products." Change the price, save.
- Click Delete on the product: "And delete products — notice the confirmation dialog."
- Navigate to Orders: "The orders page shows all order details."
- Change an order status dropdown and click Update: "We can update order status inline."
- Click Cancel on an order: "Cancelling triggers CASCADE delete of order items and shipping."
- "All operations show success or error messages via flash notifications."

[8:30-9:00] SYSTEM OVERVIEW & CONCLUSION
- "In summary, our database handles the full purchase lifecycle: browsing products,
  placing orders, tracking shipping, and managing reviews."
- "Normalization to 3NF ensures no redundant data, and views make reporting easy."
- "The Flask frontend demonstrates all four CRUD operations against the live database."
- "Thank you for watching!"
